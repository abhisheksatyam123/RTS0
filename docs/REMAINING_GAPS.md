## Read this first: whole-game parity (refreshed 2026-10-08, evening)

The G1–G10 table below grades individual systems against 0 A.D.'s semantics, and `python3 tools/check_parity.py` reports 92% for them. Those scores are self-graded and only cover the systems listed. Judged by what a match actually plays like, RTS0 is still **a little over half way** to 0 A.D. That is an estimate from a code-only re-audit of main at `bff4f1c` (rechecked against `d8dd7af`, which adds a Gaia owner for defeated players' leftovers and sea fish) against 0 A.D.'s simulation components, UnitAI, session GUI, `config/default.cfg` hotkeys, game setup, gaia templates and renderer.

Content breadth moved up since the afternoon: 44 skirmish and scenario maps and 45 random map types, gates and structure upgrades, siege packing and siege garrisons, Petra diplomacy, tribute and trade toward every player, ship trade, and population cap, ceasefire, revealed map and allied victory in Game Setup. The estimate did not move because this audit read unit behaviour line by line, and found core 0 A.D. rules that earlier audits missed (the first list below). These matter more to how a match plays than the content that landed.

### Core behaviour gaps found 2026-10-08 (checked in code)

These are the biggest gaps between a RTS0 match and a 0 A.D. one, ordered by impact. None has an owner yet; the coordinator assigns them. The full list, including the session UI, menus, data and rendering, is under [Unowned gaps](#unowned-gaps-2026-10-08-audit).

1. ~~**A move order gets hijacked.**~~ Fixed by the unit orders PR: a plain move is UnitAI's WALKING and ignores enemies, attack-move is WALKANDFIGHT, and stance leash and range (`ShouldAbandonChase`, `GetQueryRange`) apply to targets a unit picks itself.
2. **Hunting can't kill anything.** `order_hunt` puts a fauna id in `target_unit_id`, which `lookup_unit` can't resolve, and nothing ever lowers `fauna_.hp`, so animals never die and the carcass is never spawned (`order_hunt` ~10259, `tick_fauna`).
3. **Citizen soldiers can't gather.** `tick_gather` only lets villagers, female citizens, worker elephants and fishing boats gather (~3221), and every gatherer uses one flat rate. 0 A.D.'s economy is built on infantry and cavalry gathering at per-class `ResourceGatherer` rates.
4. **Units idle when a resource runs out.** A unit whose tree or mine runs out goes idle while still carrying its load instead of finding the next one (~3301). Women now default to passive and flee 12 m from attackers (unit orders PR).
5. ~~**Capture happens by standing near a building.**~~ Fixed by the unit orders PR: only units ordered to capture do so (Attack.js Capture, 4 m, once per second), and Ctrl+right-click attacks instead. Per-template capture resistance is still missing.
6. **Buildings can be placed anywhere.** `can_place` checks only map bounds and occupied cells (~875): no own-territory rule, no distance between Civic Centres, no unit obstruction (0 A.D. `BuildRestrictions.js`).
7. **No batch training, and no training limits.** One unit per queue slot with no batch time discount, and no one-hero-at-a-time rule (0 A.D. `Trainer.js`, `EntityLimits.js`).
8. **Single-player Game Setup ignores the player count.** Random maps always generate 2 players (4 on Mediterranean) because `main_node.cpp` passes a fixed `num_p`, and the single-player path never reads `slot_types` or calls `set_player_active`, so 3–8 slots and extra AIs only work in multiplayer (~3369).
9. **Siege engines and towers pick the wrong targets.** Rams auto-attack infantry because no restricted-classes check exists; towers always shoot the first unit in range (0 A.D. `Attack.js` RestrictedClasses, `BuildingAI.js`).
10. ~~**Guard and patrol are broken.**~~ Fixed by the unit orders PR (Guard.js, UnitAI PATROL).
