# 0 A.D. code migration: status and todo

This file tracks the migration of the vendored 0 A.D. C++ in `src/0ad/` (reference only; `SConstruct` skips it) into live RTS0 code. Update it in every PR that ports, changes or drops a piece. Gameplay parity with 0 A.D.'s JS systems is tracked separately in `docs/REMAINING_GAPS.md` and `docs/PLAN.md`. 0 A.D. data imported by tools rather than ported code (assets, maps, unit rosters and heroes from `tools/extract_0ad_rosters.py`) is listed in `docs/0AD_ATTRIBUTION.md`.

Last updated: 2026-10-10 (placement against turned footprints).

Status key: **Done**, ported and in use · **Ported**, ported and tested but not used by the sim yet · **Partial** · **Todo** · **Not planned**

## Todo, in priority order

This list covers porting the vendored C++ only. Overall project priorities and gameplay-parity work are in `docs/PLAN.md` and `docs/NEXT_STEPS.md`; this list doesn't repeat them.

1. **Obstruction shapes.** Rasterization is done, and building footprints are rectangles that turn with the building (`nav/footprint.h`, the axes of `CCmpObstruction::GetObstructionSquare`) in the nav grid, short paths, `separation()`, gates and reach checks. A building has a half width (`half_size`) and a half depth (`half_d`, from `building_half_depth`, equal for every building so far), and a quarter turn swaps them (`Building::hu`, `hv`). 0 A.D.'s `CCmpObstructionManager` isn't vendored, and RTS0 doesn't need a full one: `buildings_` and the `UnitGrid` in `separation()` give VertexPathfinder its shapes. Placement follows `CCmpObstruction::CheckFoundation`: every building marks the grid cells its turned footprint reaches into (`occupied_cells_`, FULL where it covers a cell, PART where it only reaches in), so a square of whole cells is blocked wherever a footprint overlaps it, and a turned foundation is tested shape against shape where it only shares PART cells (`CCmpObstructionManager::TestStaticShape`, `nav::footprints_overlap`). A destroyed or deleted structure no longer blocks its ground (a 0 A.D. corpse has no Obstruction). Units keep their 0 A.D. passability class Clearance from buildings (`unit_building_clearance`: 0.8 m, 3 m for the "large" class of siege and elephants), but between units RTS0 keeps its own `unit_collision_radius`, where 0 A.D. gives the obstruction the clearance too. Range checks against structures (attack, capture, build and repair, dropsite returns, trade arrival) measure IsInTargetRange's gap between the unit's circle and the turned footprint (`structure_gap`), not the distance to the centre.
2. **Unit pushing.** Done. `separation()` ports `CCmpUnitMotionManager`'s pushing (`CCmpUnitMotion_System.cpp` `Push`, `pathfinder.xml` `<Pushing>`): moving units push moving units and idle units push idle units, never one another; a pair pushes within its clearances times Radius plus the moving or static extension, at a force that peaks at Spread of that reach and is capped by `MAX_DISTANCE_FACTOR`; the heavier unit pushes harder (UnitMotion Weight: 10, 50 for siege and elephants); units that have walked through each other get the sideways nudge; and a unit's total push under MinimalForce per turn is dropped, so crowds settle. A formation's members don't push each other while they hold their slots. Units standing still obstruct a walker (`avoid_idle_units`, `CheckMovement`'s `ControlGroupMovementObstructionFilter`), which stops and takes a short path round them (`search_short_path_with_units`, `HandleObstructedMove`'s range of 12 m plus 4 m per failed turn, at 4 m a unit). RTS0 keeps only the path's next waypoint, so a walker that reaches one searches on from there, 32 m round, instead of heading back to where it was stuck. The path leads to the task's range round its target once that is in the search range, shaped as `ComputeGoal` shapes it (a circle round a unit or resource, a square round a structure), and a walker already within reach of its task stays where it is. RTS0 keeps `unit_collision_radius` for bodies and gives pushing 0 A.D.'s clearances scaled to it (`unit_push_clearance`, `PUSH_SCALE`), so two villagers still settle 1.4 units apart. Pushing pressure (`MotionState::pushingPressure`, kept in `MotionTurn`'s spare byte, so the save format doesn't change) builds up once per turn with each pair that pushes, decays by PressureDecay, dampens a unit's pushes and slows its walk to no less than 1.5 m/s (`PerformMove`, `unit_move_speed`). Left: a ship's passengers still come ashore on one spot and push their way apart, where 0 A.D. picks a free spot for each (`Footprint.PickSpawnPoint`, which #264 ported for trained and ungarrisoned units).
3. **JumpPointCache.** Not needed yet. Maps now reach 512, but on 2026-10-08 JPS long paths were only about 3% of a 20-minute Mainland match on a 512 map (callgrind). Revisit if that share grows.
4. **Fixed-point simulation (optional).** Whether the sim moves from `float` to `rtso::Fixed` is a multiplayer-model decision. See `docs/PLAN.md` P5 and `docs/MULTIPLAYER.md`. `src/core/math/fixed.h` is ready if that decision is made. It would also need `CFixedVector2D`, which isn't vendored.
